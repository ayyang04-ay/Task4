# Does the prompt or data room impose each requirement? (reviewer's ambiguity test)

The reviewer's test: a requirement stated in the prompt or data room supports a valid failure mode; an
implicit expert norm not stated anywhere is task ambiguity instead.

## Mode 1 - the lack of any protection endpoint goes unstated. STATED. Valid.

The prompt requires it in terms: "Start with what the current data establish about the candidate **and where
they fall short**". The complete absence of a protection, efficacy or challenge endpoint is the largest
shortfall in the record, so reporting it falls inside an explicit instruction, not an expert norm.

Stronger still, every one of the sixteen runs created a section titled on where the data fall short, by heading,
in direct response to that instruction. So the requirement was recognised and acted on by the whole panel. The
item is missing from a section the runs themselves built for it. That forecloses the ambiguity objection:
the runs cannot be said to have lacked notice of a requirement they each structured their deliverable around.

Worth stating this basis in the FA explicitly, since the reviewer asked for it.

## Mode 3 - cross-dose comparison not reconciled. STATED, if framed as method rather than citation. Valid.

Nothing in the prompt or dossier instructs a model to cite the conventions it relies on. So "name the baseline
convention" is exposed to the ambiguity objection as a reporting-format expectation.

But the substance is not a citation requirement. The prompt identifies the dossier as "our programme's assay
and analysis reference", and the dossier's own opening states that it "States the methods and conventions used
to generate the mounted datasets". The registry's DE-gene outcome measure repeats the reference-frame rule in
its own description. So the record states, twice, how the two sets of counts were constructed. Comparing them
as like quantities misuses the data as built, whether or not any instruction tells the model to cite a
convention.

Implication for wording: keep the first paragraph's framing, "fail to establish a fair/uniform comparison in
baselines", which is a method claim. Change the second paragraph's "Name the baseline conventions its using",
which is a citation claim and the weaker ground.

## Mode 2 - no work proposed to bridge the gap. WEAKEST on this test.

The prompt requires "the studies that follow from it" and "the next studies you considered and set aside, with
why". It therefore permits setting a study aside, provided a reason is given. Every run set field efficacy and
human challenge aside and gave a reason, which is compliance with the instruction as written. Nothing in the
prompt or data room says every shortfall must carry a proposed study.

So "no run proposes compensatory studies" is accurate as a description of conduct but is not clearly a
violation of a stated requirement. This is the mode most likely to be pinged as an implicit expectation.
Options: drop it, fold it into Mode 1 as the consequence of the unstated gap, or keep it and state plainly that
the runs complied with the set-aside instruction while leaving the shortfall unaddressed.

## Positive-aspect phrases to remove from the failure-mode paragraph

Per the reviewer, no positive description belongs in the failure modes:

- "are great at logging/inventorying all the data (as a table or a unified section)" - praise. The fact that
  matters is only that each had the full inventory in view.
- "(which is reasonable)" - endorses the dismissal inside a failure mode.
- "Run12 is the closest to addressing this" - ranks it favourably.
- "Run08 and run16 do state it, but ..." - "do state it" reads as credit. The fact is that they placed it in a
  set-aside rather than among the gaps.
